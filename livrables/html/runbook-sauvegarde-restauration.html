Runbook — Sauvegarde, nettoyage RGPD et restauration (MiniShop)

Propriétaire : Équipe Exploitation / DBA MiniShop · Références : docs/18-politique-conservation.md, scripts/db_init.php, app/Service/

1. Tâche planifiée de rétention RGPD (--nettoyage)

Exécutée hors pic de trafic (cron ou systemd avec Persistent=true en V1 ; CronJob concurrencyPolicy: Forbid en orchestrateur, § 4.1.12) :

# Aperçu sans suppression (dry-run recommandé après mise à jour)
php scripts/db_init.php --nettoyage --simulation

# Exécution réelle : purge comptes inactifs, journaux expirés et archives obsolètes
php scripts/db_init.php --nettoyage

Services déclenchés dans l’ordre : RetentionComptes (comptes sans commande au-delà du seuil), NettoyageJournaux (var/journal/db.jsonl, var/log/contact.jsonl) et NettoyageSauvegardes (archives chiffrées libsodium dans le répertoire dédié).

2. Sauvegarde complète avant intervention (mysqldump cohérent)

DATE_UTC=$(date -u +%Y%m%dT%H%M%SZ)
mysqldump --single-transaction --routines --triggers --events minishop > "/srv/backups/minishop_${DATE_UTC}.sql"
sha256sum "/srv/backups/minishop_${DATE_UTC}.sql" > "/srv/backups/minishop_${DATE_UTC}.sha256"

Les options --routines --triggers sont obligatoires pour sauvegarder les 18 procédures stockées et 16 déclencheurs livrés dans sql/02 et sql/03.

3. Procédure de restauration et vérification (sur base dédiée)

  1. Vérifier l’empreinte SHA-256 de la sauvegarde avant toute restauration : bash sha256sum -c "/srv/backups/minishop_${DATE_UTC}.sha256"
  2. Restaurer sur une base de validation isolée (jamais directement sur la prod sans test préalable) : bash mariadb -e "CREATE DATABASE IF NOT EXISTS minishop_restore CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;" mariadb minishop_restore < "/srv/backups/minishop_${DATE_UTC}.sql"
  3. Contrôler l’intégrité des objets SQL (9 tables, 4 vues, 18 procédures, 1 fonction, 16 déclencheurs) : bash mariadb -N -e "SELECT COUNT(*) FROM information_schema.ROUTINES WHERE ROUTINE_SCHEMA='minishop_restore';" mariadb -N -e "SELECT COUNT(*) FROM information_schema.TRIGGERS WHERE TRIGGER_SCHEMA='minishop_restore';"
  4. Tester l’application en pointant un environnement de recette sur minishop_restore, puis basculer ou supprimer minishop_restore une fois le contrôle validé.
