Fiche de service — MiniShop (Boutique & Back-office)

Propriétaire : Équipe MiniShop · Criticité : Service transactionnel e-commerce · Dernière vérification : 2026-11-16

1. Identité du service

  • Point d’entrée HTTP : public/index.php (app/Router.php, PHP 8.2+)
  • Configuration locale / prod : .env (hors Git, modèle .env.example, lu par app/Config/Env.php)
  • Mode de stockage production : STORAGE_DRIVER=sql (MariaDB 10.6+ / 11.8.6 via app/Model/Data/SqlStore.php)
  • Journaux locaux V1 : var/journal/db.jsonl (Journal.php), var/log/contact.jsonl (HomeController.php), error_log PHP
  • Maintenance CLI : php scripts/db_init.php --nettoyage (RetentionComptes, NettoyageJournaux, NettoyageSauvegardes)

2. Dépendances et rayon d’impact

Dépendance Type Rôle Effet si indisponible
MariaDB (minishop) Service consommé critique Catalogue, paniers persistés, commandes (sp_*), comptes HTTP 500 sur toutes les routes SQL
Système de fichiers var/ Stockage local V1 Sessions PHP (MINISHOPSESS), journaux JSONL Journaux ignorés (Journal::create() non bloquant) ; sessions coupées si plein
CDN / WAF / IdP (cible prod) Bordure & identité (§ 4.1.13, 5.1.3) TLS, filtrage L7, SSO sso.minishop.fr Sessions JWT actives maintenues jusqu’à expiration ; nouvelles connexions bloquées (secours break-glass requis)

3. Objectifs de niveau de service (référence ENF-01)

  • Latence HTTP mesurée (VM Debian 13) : p95 = 6,0 ms sur les routes catalogue/produit (tests/perf/dernieres_mesures.txt).
  • Latence SQL mesurée : p95 <= 20,6 ms en lecture/recherche, 44 ms sur sp_create_order_from_basket.
  • Commandes rapides de santé :
  • php scripts/run-all-tests.php --sans-sql --sans-e2e (contrôle applicatif isolé)
  • bash tests/security/controles.sh (11 contrôles statiques de sécurité)
