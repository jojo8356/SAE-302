08 — Fiche de suivi des commits (rejeu vers un nouveau GitLab)#

Objet. Décrire un scénario synthétique de rejeu du projet sur un nouveau dépôt GitLab, avec 32 commits proposés, des messages prêts à copier-coller et un périmètre de fichiers. Ce scénario est un plan, non un journal d'exécution ni une reconstitution certifiée de l'historique. La fiche et scripts/rejeu_gitlab.py partagent le même plan ; le mode de rejeu vers un dépôt externe ne doit pas être utilisé sans demande explicite et vérification préalable de sa compatibilité.

Note de portée (23/10/2026). Les entrées É5 (86 tâches) et É27 (GitLab CI) décrivent un périmètre historique ; la WBS courante compte 84 tâches et la CI GitLab a été retirée. Le scénario proposé ne comporte plus d’automatisation de mise en ligne. Aucune exécution de ce rejeu n’est revendiquée.

1. Mode d'emploi express#

# 1) Créer sur GitLab le projet vide « minishop-sae » (NE PAS cocher « Initialize with a README »)
# 2) Depuis ce dépôt, reconstruire l'historique dans une copie isolée :
python3 scripts/rejeu_gitlab.py --dest ../minishop-sae \
    --nom "Prénom Nom" --email prenom.nom@etu.univ-cotedazur.fr
# 3) Vérifier, puis pousser :
cd ../minishop-sae && git log --oneline
git remote add origin https://gitlab.example.fr/<groupe>/minishop-sae.git
git push -u origin main --tags

Le script n'écrit jamais dans le dépôt courant : il extrait une copie propre (« git archive ») dans --dest, y rejoue les 32 commits + les 6 tags de jalons, puis contrôle que l'arbre final est identique, fichier pour fichier.

Le rejeu manuel (copier-coller des git add + messages ci-dessous) est bien sûr possible : c'est le §3.
