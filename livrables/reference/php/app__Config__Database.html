App\Config · app/Config/Database.php

Database

Description

MiniShop — point d'accès unique à la couche de données (annexe 17.7 §1). Database::store() retourne le pilote choisi par l'énumération App\Model\Data\StorageDriver : 'storage_driver' => 'sql' → SqlStore (pilote principal, MySQL/MariaDB via PDO) 'storage_driver' => 'json' → JsonStore (option secondaire sans serveur) La configuration est lue dans cet ordre (le dernier gagne) : 1. valeurs par défaut ci-dessous ; 2. `app/Config/env.php` (compatibilité avec l'ancien modèle) ; 3. fichier **`.env`** à la racine, modèle versionné `.env.example` — c'est le mode recommandé : copier, éditer, ne jamais committer ; 4. variables d'environnement du processus (CI, conteneur, test ponctuel). Le pilote SQL est sélectionné par défaut ; configurer la base locale : cp .env.example .env # .env : DB_NAME="minishop" DB_USER="minishop" DB_PASSWORD="…" # DB_SOCKET="" (vide = TCP 127.0.0.1:3306, repli automatique sur la # socket Unix si le compte n'accepte que ce mode — cas de root sur Debian) php scripts/db_init.php # initialise le schéma, 18 procédures, 1 fonction et 16 triggers Les contrôleurs et les repositories ne connaissent QUE StoreInterface.
