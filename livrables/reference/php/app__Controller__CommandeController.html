CommandeController

Description

MiniShop — validation, historique, détail et annulation des commandes (UC-07/08/09, EF-CLI-07…10, RB-04/06/08/10/11/15/18/20, SEC-08). Le contrôle d'appartenance est systématique côté serveur (SEC-08) : une requête portant l'identifiant d'une commande absente ou d'un AUTRE client répond 404 générique (COMMANDE_INTROUVABLE), sans révéler l'existence de la ressource (test S-04 du document de tests).

Méthodes publiques (6)

public function formulaire(): void

Étape 1 — récapitulatif + adresse de livraison (port affiché AVANT validation, art. L221-5).

public function valider(): void

Étape 2 — validation : création transactionnelle depuis le panier
(UC-07), panier vidé ensuite (EF-GEN-02), stock décrémenté par les
déclencheurs (RB-18), prix et port figés (RB-06/RB-20).

public function mes(): void

UC-08 — historique des commandes du client (EF-CLI-08).

public function detail(string $id): void

UC-08 — détail d'une de ses commandes (EF-CLI-09) + piste de statuts.

public function confirmerAnnulation(string $id): void

Étape de confirmation avant annulation : l'annulation est
définitive, un simple clic ne doit pas y suffire. Cette page
(GET, sans effet de bord) demande « Êtes-vous sûr ? » ; seul le
POST annuler() exécute. Même garde qu'annuler() : appartenance
(SEC-08) et commande encore annulable.

public function annuler(string $id): void

UC-09 — annulation tant que non expédiée (EF-CLI-10, RB-11/18/20).
