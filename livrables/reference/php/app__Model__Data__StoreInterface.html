StoreInterface

Description

MiniShop — contrat commun des pilotes de gestion des données. Ce contrat définit la frontière commune des opérations de stockage entre les repositories et les pilotes SQL/JSON : chaque méthode correspond à une opération relationnelle standard, mais AUCUNE méthode ne reçoit ni ne produit du SQL — les filtres sont déclaratifs (tableaux sérialisables). Les capacités propres à certains pilotes (procédures stockées, verrous de lignes) sont des interfaces séparées : le pilote JSON n'a pas à les simuler. --------------------------------------------------------------------------- Spécification déclarative des filtres (« where ») --------------------------------------------------------------------------- Une condition est un tableau numérique : [colonne, opérateur, valeur] opérateurs : = != <> < <= > >= like not-like in not-in between null not-null - « like » est insensible à la casse ET aux accents (comme la collation utf8mb4_unicode_ci du schéma MySQL cible), jokers % et _. - « in » / « not-in » : valeur = tableau de valeurs. - « between » : valeur = [min, max] (bornes incluses). - « null » / « not-null » : pas de valeur. Un « where » est une liste de conditions combinées par AND implicite : [['visible', '=', 1], ['prix_ttc', 'between', [20, 100]]] Des groupes explicites sont possibles : [['or', [[['nom','like','%clavier%'], [['reference','like','%CLAV%']]]]] JsonStore évalue ces conditions en PHP ; SqlStore traduit les opérateurs génériques en clauses SQL préparées. Les parcours métier qui le nécessitent peuvent aussi appeler des procédures via les interfaces de capacité. --------------------------------------------------------------------------- Spécification des tris (« order ») --------------------------------------------------------------------------- [['colonne', 'asc'|'desc'], ...] — multi-clés, stable. --------------------------------------------------------------------------- Cycle de vie et intégrité --------------------------------------------------------------------------- insert()/update()/delete() appliquent le schéma et les déclencheurs métier du pilote actif : validation PHP/Triggers pour JsonStore, contraintes et triggers SQL pour SqlStore. Les écritures applicatives multi-tables passent par beginTransaction()/commit() avec rollback automatique en cas d'exception (ENF-16) ; les procédures SQL qui possèdent leur transaction sont appelées sans transaction englobante.
