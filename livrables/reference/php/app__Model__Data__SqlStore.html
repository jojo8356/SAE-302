SqlStore

Description

MiniShop — pilote SQL (MySQL / MariaDB via PDO). Implémente le contrat commun StoreInterface et expose séparément les capacités SQL spécialisées (procédures stockées et verrouillage de lignes). Les contrôleurs et repositories consomment ces capacités via des interfaces, sans dépendre de cette classe concrète. Le pilote est choisi par la configuration (`storage_driver = 'sql'`, cf. StorageDriver) : « SQL » → SqlStore : MySQL/MariaDB, règles appliquées par la base (CHECK, clés étrangères, 16 déclencheurs, 1 fonction + 18 procédures de sql/01→03) « JSON » → JsonStore : moteur secondaire, règles appliquées en PHP Principes de sécurité (SEC-01) : - AUCUNE valeur n'est concaténée dans le SQL : tout passe par des marqueurs `?` et des requêtes préparées natives (PDO::ATTR_EMULATE_PREPARES = false) ; - les noms de tables et de colonnes sont validés contre le SCHÉMA (liste blanche Schema::tables()), jamais contre une entrée utilisateur ; - les opérateurs sont limités à une table de correspondance fermée. Transactions : `beginTransaction/commit/rollback` sont délégués à PDO. L'acteur courant est mémorisé en PHP : il sert à appeler les procédures qui tracent l'auteur (historique de statut, mouvements de stock).

public function callProcedure(string $procedure, array $entrees = [], array $sorties = []): array

`CALL` d'une procédure, paramètres OUT retournés sous la clé `out`.

Forme attendue par les dépôts (App\Repository\*) qui passent par les
procédures stockées quand le pilote SQL est actif :

$r = $store->callProcedure('sp_create_order', [$idClient, $adresse],
['id_commande', 'numero']);
$id = (int) $r['out']['id_commande'];

C'est un adaptateur de `appeler()` : éviter deux variantes de la même
logique (une seule implémentation, testée).
