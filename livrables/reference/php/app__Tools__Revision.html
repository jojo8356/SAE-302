Revision

Description

MiniShop — empreinte de la révision du code affichée par les scripts. Pourquoi : `scripts/db_init.php` et `run.sh` peuvent être exécutés depuis une copie partiellement mise à jour (fichiers récupérés un par un, `git checkout` incomplet). Le symptôme est trompeur — un message d'erreur d'une révision antérieure ressemble à un bug de la révision courante. Afficher l'empreinte rend la confusion immédiatement visible : il suffit de comparer avec `git log -1 --oneline`. Aucune dépendance : `git` est appelé en silence, et l'absence de dépôt (copie dézippée, sandbox PHP-WASM) donne « inconnue » plutôt qu'une erreur.

Méthodes publiques (4)

public static function courante(): string

Empreinte lisible : `6a7dde5 · 2026-10-27`, ou `inconnue` hors dépôt Git.

public static function synchroniseSur(): ?string

Révision sur laquelle la copie a été synchronisée (`.git/minishop-synchro`),
écrite par `scripts/maj-depuis-branche.sh` — `null` si aucune synchro n'a
eu lieu.

Une synchro de fichiers ne déplace NOTRE tête de branche : afficher
seulement `HEAD` laisserait croire que la copie est périmée alors qu'elle
vient d'être mise à jour.

Le code local est-il modifié par rapport au dernier commit ?
